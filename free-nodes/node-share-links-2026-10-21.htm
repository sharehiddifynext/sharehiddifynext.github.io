智能分流新境界：手把手教你打造Shadowrocket专属PAC代理规则

在数字化生活深度嵌入日常的今天，网络连接的效率与安全早已成为刚需。对于iOS用户而言，Shadowrocket（俗称“小火箭”）凭借其强大的协议兼容性和灵活的规则定制能力，始终占据着工具链中的关键位置。然而，许多用户在享受其基础代理功能时，往往忽略了PAC（Proxy Auto Configuration）这一“隐藏神器”——它能让你的网络请求如丝般顺滑地在直连与代理之间自动切换，既保留国内站点的极速访问，又确保海外资源畅通无阻。

本文将以实战为导向，从PAC的底层逻辑出发，手把手带你完成从获取规则到最终生效的全流程配置，并针对高频痛点给出解决方案。无论你是刚入门的“新司机”，还是追求极致效率的“老玩家”，这篇攻略都能让你对Shadowrocket的控制力提升一个维度。

一、PAC：不止是“自动代理”那么简单

在深入配置之前，我们有必要先拆解PAC的本质。PAC并非一个具体的代理服务器，而是一段用JavaScript编写的函数脚本，它像一位“交通警察”，站在你的设备与互联网之间，根据预设的规则（如域名、IP段、请求协议等）为每一个访问请求分配最优路径——是直接连接，还是经由特定代理服务器转发。

1.1 从“全局代理”到“智能分流”的进化

  • 全局代理：所有流量都走代理，简单粗暴，但代价是访问国内网站时绕远路，速度反降。
  • PAC模式：通过规则判断，让国内外流量各走其道。比如访问google.com时走代理，访问baidu.com时直连。这正是PAC的核心价值——精准、高效、省流量。

1.2 PAC的三大核心优势

  • 动态可调：规则文件独立于应用，修改无需重启，即时生效。
  • 高容错性：即使代理节点故障，PAC也能通过isResolvable()或dnsDomainIs等函数实现故障转移。
  • 隐私增强：敏感域名走代理，避免DNS泄露，降低被审查风险。

二、Shadowrocket前置准备：基础功必须扎实

在开始PAC配置前，请确保你的Shadowrocket处于健康状态：

  1. 版本更新：前往App Store检查是否有新版本。老版本可能缺乏对最新PAC语法或IPv6的支持。
  2. 基础连通性：先手动添加一个可用的代理节点（如SS/SSR/Vmess），并确认在“全局代理”下能正常访问外网。这能排除底层网络故障，让后续PAC调试更聚焦。
  3. 备份现有配置：若你已有自定义规则，建议先导出配置文件备份，避免误操作导致丢失。

三、核心实战：PAC配置五步走

步骤1：获取高质量PAC文件链接

PAC文件的质量直接决定分流效果。推荐渠道：

  • GitHub开源项目：搜索“Shadowrocket PAC”或“gfwlist2pac”，这类项目通常维护着实时更新的规则列表，能覆盖绝大多数被墙站点。
  • 专业博客/论坛：如“Loyalsoldier”的规则集，支持自定义白名单/黑名单模式。
  • 自建PAC：若你熟悉JavaScript，可基于gfwlist或ChinaList生成专属文件，实现100%个性化。

安全警示：切勿轻信来源不明的短链接PAC，防止恶意脚本劫持你的流量。下载后建议用文本编辑器打开，查看是否存在eval、exec等危险函数。

步骤2：进入Shadowrocket配置界面

打开Shadowrocket，点击首页右上角的 “+” 号。此时你会看到多种配置类型选项，包括“手动添加节点”、“订阅”等。滑动至底部，找到 “类型” 切换按钮，点击并选择 “Auto Proxy” 或直接显示为 “PAC” 的选项。

步骤3：粘贴PAC链接或上传本地文件

  • 远程链接：在URL输入框中粘贴你获取的PAC文件直链（以.js或.pac结尾）。注意：链接需以http://或https://开头，且服务器需支持CORS（跨域资源共享），否则Shadowrocket可能无法拉取。
  • 本地导入：若你已将PAC文件下载至手机，可通过“文件”App共享至Shadowrocket，或使用iTunes文件共享功能拷贝至App的Documents目录。在配置界面选择“本地文件”并定位到该文件即可。

步骤4：配置代理模式与容灾策略

PAC模式并非孤立工作，它需要与节点策略协同：

  • 代理节点：在“代理”栏中，选择一个作为PAC规则中“PROXY”指令的落脚点。建议选择延迟低、稳定性好的节点。
  • 失败回退：在PAC配置下方，通常有“Fallback”设置。建议勾选“Direct”作为兜底，这意味着当PAC脚本执行出错或无法解析时，自动切换为直连，避免断网。
  • 强制代理域名：部分PAC规则会忽略某些域名（如apple.com），你可以通过“额外规则”手动追加，确保这些域名强制走代理。

步骤5：保存、激活与验证

点击右上角“保存”后，返回Shadowrocket首页。此时你会看到新配置卡片出现在列表中。点击卡片右侧的开关按钮，将其激活（状态变为绿色）。随后，打开Safari浏览器，分别测试以下场景：

  • 访问http://www.baidu.com：应直接加载，无代理延迟。
  • 访问https://www.youtube.com：应能正常播放，且延迟与所选节点匹配。
  • 访问http://whatismyip.com：显示的IP应为代理节点所在地区。

若上述测试均通过，恭喜你，PAC分流已成功生效！

四、进阶修炼：个性化规则定制与动态更新

4.1 手写规则：从“使用者”到“创作者”

PAC脚本的核心是FindProxyForURL(url, host)函数。一个最简示例：

javascript function FindProxyForURL(url, host) { if (host == "twitter.com" || host.endsWith(".youtube.com")) { return "PROXY 127.0.0.1:1080; DIRECT"; } return "DIRECT"; }

你可以通过以下常用函数丰富规则：

  • shExpMatch(host, "*.google.*")：通配符匹配。
  • dnsDomainIs(host, ".google.com")：后缀匹配。
  • isInNet(host, "10.0.0.0", "255.0.0.0")：IP段匹配。
  • myIpAddress()：获取本机IP，可用于实现“局域网内直连”等高级逻辑。

4.2 让规则“保鲜”：自动更新的艺术

网络环境日新月异，新被墙域名层出不穷。手动更新PAC链接显然不现实。解决方案：

  • 利用GitHub Actions：许多开源PAC项目会定期自动生成并推送最新文件。你只需在Shadowrocket的配置中开启“自动更新”开关，并设置更新间隔（如24小时）。
  • 借助第三方订阅转换：部分服务商提供“PAC订阅”功能，将多个规则源合并为单一链接。但这需要信任第三方服务，建议仅从信誉良好的服务商获取。

五、常见问题深度排雷

问题1：PAC文件明明有效，但规则不生效？

  • 排查步骤：
    1. 检查Shadowrocket是否处于“PAC模式”，而非“全局模式”。
    2. 在PAC脚本中临时添加alert(host);，然后通过Safari访问一个测试站点，用Xcode的Console查看日志，确认脚本是否执行。
    3. 确认节点本身可用——尝试切换到“全局模式”访问同一站点，若仍失败，则是节点问题。

问题2：PAC模式下访问国内网站速度变慢？

  • 原因：PAC规则可能将某些国内域名误判为“被墙”，导致流量绕行海外节点。
  • 解决：在PAC规则中追加“直连”白名单。例如添加if (host.endsWith(".cn")) return "DIRECT";。或者使用基于ChinaList生成的PAC，这类规则已内置国内域名直连策略。

问题3：PAC文件下载失败或解析超时？

  • 原因：链接不可访问、服务器不支持HTTPS、或PAC文件体积过大（超过1MB）。
  • 解决：尝试用浏览器直接打开PAC链接，若无法访问则更换源。若文件过大，可寻找精简版规则，或使用本地导入方式。

问题4：如何快速切换不同PAC规则？

  • 技巧：在Shadowrocket首页，长按某个配置卡片，选择“复制”，然后修改新配置中的PAC链接，即可实现多套规则并行。配合快捷指令（Shortcuts），甚至可以实现“一键换配置”。

六、总结与前瞻：PAC的边界与未来

PAC为Shadowrocket带来了“智能”的底色，但它并非万能。对于需要基于地理位置、网络类型（Wi-Fi/蜂窝数据）进行动态切换的场景，PAC略显力不从心。此时，你可以考虑结合Shadowrocket的“分组”功能或利用iOS 16+的“专注模式”自动化，实现更精细的场景化分流。

此外，随着DoH（DNS over HTTPS）和DoT（DNS over TLS）的普及，PAC脚本中的DNS解析环节也需要与时俱进。建议在Shadowrocket的“DNS”设置中，为代理通道开启“加密DNS”，避免DNS污染影响PAC的判断结果。

写在最后：PAC不是冷冰冰的代码，而是你与互联网世界之间的一道智能阀门。花15分钟完成本攻略的配置，你将告别手动切换代理的繁琐，迎来“无感”畅游网络的新体验。记住，最好的规则是“无规则”——当分流足够精准时，你几乎感知不到它的存在，但每一次访问都恰到好处。

Sing-box 如何实现流量精细分流？
通过定义 routing 规则和策略组，Sing-box 可以根据域名、IP、端口或协议类型精细分流流量。例如视频走高速节点，网页走备用节点，实现流量优化和网络加速。
Hiddify Next 用户流量配额如何设置？
管理员可为每个用户设置带宽和流量上限，超出限制可自动降速或阻止访问，保证服务器资源合理分配，避免单用户占用过多带宽，提高整体网络公平性和使用效率。
Netch 是否支持系统代理？
Netch 不直接修改系统代理，而是通过虚拟网卡（TAP 驱动）实现透明代理。这种方式不会影响浏览器设置，适合游戏和应用程序需要 UDP 支持的场景。
V2Ray 的 ws+tls 传输模式有什么优点？
ws+tls 模式利用 WebSocket 伪装成普通 HTTPS 流量，使得防火墙难以区分代理与正常访问。该模式兼容性强，适合部署在支持 Nginx 或 Caddy 的 Web 服务器上。
Sing-box 的配置文件与 Clash 有何区别？
Sing-box 的配置使用 JSON 格式，而 Clash 采用 YAML 格式。前者更适合程序自动解析，后者更便于人工编辑。Sing-box 在性能和扩展性上有明显优势，支持更细粒度的流量控制。
VLESS + XTLS 对高延迟网络有哪些优化？
XTLS 模式减少握手和加密开销，适合高延迟或不稳定网络环境。结合策略组和节点切换，可提高网页浏览、视频播放和游戏的稳定性和流畅度，改善用户体验。
Potatso Lite 是否可以手动管理多个节点？
支持。用户可以手动输入节点参数或扫描二维码导入节点，并可进行修改或删除。虽然不支持订阅自动更新，但足够满足轻量用户对节点管理和分流的基本需求。
Sing-box 精确端口分流如何提升游戏连接？
Sing-box 可按端口设置流量分流规则，将游戏流量分配到低延迟节点。结合策略组使用，可保证游戏连接稳定，减少延迟和掉线，提高流畅度和网络体验。
